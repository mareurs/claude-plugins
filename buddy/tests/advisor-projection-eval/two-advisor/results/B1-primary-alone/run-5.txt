## Edge cases the code raises that you haven't decided on

1. **`None == None` grants access.** A non-admin with `org_id=None` reading an invoice with `org_id=None` passes the check, because `None != None` is False. That may be an accidental grant, so decide the intended behavior, then pin it.
2. **Role matching is exact.** `"Admin"`, `"superadmin"`, `""` and `None` are all treated as non-admin. One parametrized row each documents that.
3. **Existence leak.** A non-admin probing ids gets 404 for missing and 403 for other-org invoices, which reveals which ids exist. If that's unintended, the fix is in the code and the test pins the new behavior. Test 6 freezes the current ordering either way.
4. **Type mismatch.** `org_id="1"` against `1` is `!=` in Python, so access is denied. This depends on the column type and is worth a row if org ids can arrive as strings.

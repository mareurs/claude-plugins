**Contract:** Given an invoice id, `get_invoice` returns `invoice.render()` if the invoice exists and the caller is an admin or belongs to the invoice's org. Otherwise it raises `NotFound` (no such invoice) or `Forbidden` (exists, but another org's).

## What the existing test covers

`test_get_invoice_returns_rendered_invoice` drives the **admin** path with `org_id` equal to the invoice's. Two weaknesses:

- **The admin and same-org conditions are conflated.** The admin's `org_id=1` matches the invoice's `org_id=1`. If someone deleted the `role != "admin"` clause entirely, the test would still pass, because the org check would let it through. The test cannot tell which branch authorized the caller.
- **`render()` is compared to itself.** `inv.render()` is probably deterministic, so this is fine, but the assertion proves only that the return value is the render output, not that it is the render of *invoice 42* rather than any invoice.

## Boundaries worth probing

- **`invoice_id` edges:** `0`, negative, `None`, a string like `"42"`, and a very large integer. Whether these should return `NotFound` or raise a different error is *not stated by the code*. That is an open contract question; pin whatever you decide.
- **Role edges:** `role=None`, `"Admin"` (case), `"admin "` (trailing space), `""`. The check is a string compare, so anything but exact `"admin"` is treated as non-admin. `"Admin"` getting denied may or may not be intended. Ask.
- **Org id edges:** `request.user.org_id` is `None` and `invoice.org_id` is `None`. They compare equal, so a user with no org can read an invoice with no org. That is the sharpest edge here and likely unintended. I have not verified whether the model allows a null `org_id`; check the schema before deciding whether this is a real bug or an impossible state.
- **Type edges:** `org_id` of `1` against `"1"` (the `!=` is strict, so this denies).

## Ordering contract (often missed)

`NotFound` is raised before `Forbidden`, so a non-admin probing a foreign invoice id gets `Forbidden` while a nonexistent id gets `NotFound`. That lets callers **enumerate which invoice ids exist**. If that matters to you, it is a security question, not a test gap, and one for the security-ibex. Whichever you choose, pin it with a test: non-admin on a foreign invoice raises `Forbidden`, not `NotFound`.

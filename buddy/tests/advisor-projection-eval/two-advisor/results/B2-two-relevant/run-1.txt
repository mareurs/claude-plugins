## Contract, stated

Given an existing invoice, an admin always receives it. A non-admin receives it only when `invoice.org_id == user.org_id`. A missing invoice raises `NotFound`. A non-admin from another org raises `Forbidden`.

## Missing tests (priority order)

1. **Non-admin, same org → returns rendered invoice.** This is the main non-admin path, and nothing covers it. It kills the `!=`→`==` flip on the role check.
2. **Non-admin, different org → `Forbidden`.** This is the core IDOR guard. Assert the exception type specifically, and also assert the response does not contain the rendered body.
3. **Admin, different org → returns the invoice.** The current test uses matching orgs, so it never proves the admin bypass. Without this, a mutation to `invoice.org_id != request.user.org_id` that drops the role clause survives.
4. **Unknown `invoice_id` → `NotFound`.** The branch is entirely uncovered.
5. **Ordering: missing invoice vs. unauthorized user.** A non-admin requesting a nonexistent id gets `NotFound`, per the current code. Pin it deliberately. It leaks existence (`Forbidden` vs `NotFound` tells a caller which ids exist). If that is not intended, it is a design question rather than a test gap, and I would raise it with security-ibex.

## Boundary list

| Parameter | Edges not yet covered |
|---|---|
| `user.role` | `"admin"` (covered), `"user"`, `None`, `""`, `"Admin"` (case), unknown role string |
| `user.org_id` | equal, different, `None` vs non-None, `0` (falsy but valid), type mismatch (`"1"` vs `1`) |

| DB | duplicate ids (`.first()` hides them), empty table |

The `None == None` case deserves a named test. A non-admin with `org_id=None` against an invoice with `org_id=None` passes the check today. Whether that is correct is a contract decision to make explicitly, not leave implicit.

## Proposed table-driven authorization test

```python
@pytest.mark.parametrize("role, user_org, inv_org, expected", [
    ("admin", 1, 1, "ok"),
    ("admin", 1, 2, "ok"),          # admin bypass across orgs
    ("user",  1, 1, "ok"),
    ("user",  1, 2, Forbidden),     # IDOR guard
    ("user",  0, 1, Forbidden),     # falsy org_id is still a real org
    ("Admin", 1, 2, Forbidden),     # role match is case-sensitive
    (None,    1, 2, Forbidden),
])
def test_get_invoice_authorization(role, user_org, inv_org, expected): ...
```

Note the loop-free parametrization carries the branching, so the test body stays arrange/act/assert. For the `"ok"` rows, assert equality with `inv.render()`. For exception rows, use `pytest.raises(expected)`.

## What is missing

**Contract (proposed):** given an authenticated user, an org they may export, and a format, the function returns that org's orders and nothing else, in that format. It emails the same body to the requester and writes one audit entry.

### 1. Core output, round-trip (highest value)
- `test_csv_body_parses_back_to_seeded_orders`: parse with `csv.reader` and compare id, total and created_at per row against the seeded values.
- `test_json_body_parses_back_to_seeded_orders`: the same via `json.loads`.
- Property form: for any generated list of orders, `parse(export(rows)) == rows`, covering conservation of count and order. Keep named boundary cases beside it.

### 2. Tenant isolation
- `test_excludes_orders_from_other_orgs`: seed org 1 and org 2, export org 1, and assert that no org-2 id appears. This is the mutation the current test misses.
- Metamorphic form: adding orders to another org never changes the output for this one.

### 3. Boundaries not covered
- **Zero rows:** CSV should be `""` and JSON `"[]"`. This is the case where `fmt` branches are most likely to diverge.
- **One row**, and a large export (the whole body goes into one email, so is there a size limit?).
- **`fmt`:** `"json"`, `"CSV"`, `""`, `None` and `"xml"`. Today every non-`"csv"` value silently becomes JSON. **Is that intended?** I can't write the assertion until you say.
- **Field values:**
  - `total` as `Decimal`, `0`, negative and `None`. **Verify:** `json.dumps` raises `TypeError` on `Decimal`, so if your driver returns `Decimal`, the JSON path crashes.
  - `created_at=None`. **Verify:** CSV writes `""` while JSON writes `"None"`, so the two formats would disagree.

### 4. Side effects, observable through fakes
Use a recording fake mailer and audit log, not spies on call counts.
- `test_emails_body_to_requesting_user`: assert recipient `a@x.io`, subject `"Your export"`, and that the body equals the return value.
- `test_writes_audit_entry_for_user_and_org`: assert the recorded entry is `("export", 7, 1)`.
- **Failure ordering:** if `mailer.send` raises, no audit entry is written. If audit raises after the mail goes out, the data has left unaudited. Which behavior do you want? Pin that choice.

## What is missing, by risk

**1. Tenant isolation (highest risk)**
- Nothing seeds a second org, so the filter is unpinned.
- The function never reads `request.user.org_id`. It trusts the `org_id` argument, so a user in org 1 can export org 2 and the test cannot notice. This is a probable IDOR. I haven't seen the caller or any route-level check, so I can't say whether it is blocked upstream. That is a question for security-ibex.
- The `f"... {org_id}"` query is injectable if `org_id` is ever a string. The test passes a clean int. Add a case with `"1 OR 1=1"` that expects a rejection or an unchanged row count. Also a question for security-ibex.
- Tests needed:
  - Seed orgs 1 and 2, export org 1, and assert that only org-1 ids appear.
  - Add a cross-org case where the user belongs to org 1 and requests org 2.

**2. The JSON branch has zero tests (branch pairing gap)**
- Needed: the `else` arm, with exact-value assertions.
- `str(r.created_at)` on `None` yields the string `"None"`. The CSV branch writes `""` for the same row, so the two formats disagree.
- `json.dumps` raises `TypeError` if `total` is a `Decimal`. I haven't verified the column type. Check it and add a case.

**3. Side effects are completely unasserted**
- Assert on a fake mailer outbox and a fake audit sink, not on call counts:
  - the recipient is `a@x.io`
  - the subject is `"Your export"`
  - the emailed body equals the returned body
  - the audit entry is `("export", 7, 1)`
- Failure ordering is unpinned. If `mailer.send` raises, no audit entry is written. If `audit_log.write` raises, the data has already been emailed with no trail. Decide the intended contract and pin it.

**4. Boundaries of the row set**
- 0 rows: CSV gives `""` and JSON gives `"[]"`. Is an empty export still emailed and audited?
- 1 row, and many rows. `fetchall()` has no size cap, so what is the limit?
- `total` as `None`, `0`, a negative, or a large `Decimal`.
- `created_at` as `None`.
- There is no `ORDER BY`, so row order is nondeterministic. Any test that asserts order will flake until the contract defines one.

**5. `fmt` handling**
- Every value that is not exactly `"csv"` silently becomes JSON, including `"CSV"`, `""`, `None` and `"xml"`. Is that intended?
- Table-drive the rows `"csv"`, `"json"`, `"CSV"`, `""`, `None` and `"xml"` once you decide.

**6. Request edge cases:** a user with no email (`None`), or an anonymous user.

## Properties to add beside the named cases

- **Round-trip:** `csv.reader` over the CSV body, and `json.loads` over the JSON body, recover the seeded `(id, total, created_at)` tuples.
- **Conservation:** the output row count equals the seeded row count for that org.
- **Metamorphic:** adding orders to another org never changes the output for this org. This catches the missing `WHERE` clause for any generated data.

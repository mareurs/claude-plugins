# Codex background wake 0.167.0 implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline. Do not delegate.

**Goal:** Add measured Linux Codex 0.167.0 support without weakening callback ownership or root-origin checks.

**Architecture:** Preserve the existing adapter and native intake. Centralize their measured compatibility declarations, test both version combinations and mismatch rejection, and provide an opt-in native primary/secondary probe whose results must be observed before claiming 0.167.0 support.

**Tech Stack:** Node.js ESM, node:test, ws, Codex app-server JSON-RPC.

**Spec:** ../specs/2026-11-10-codex-wake-0167-design.md (approved in conversation).

## Global constraints

- Keep legacy daemon 0.160.0 and CLI 0.165.0 behavior.
- Only measured daemon 0.167.0 and CLI 0.167.0 are eligible for additional support.
- Preserve exact profile and socket generation checks, root/child discrimination, no-retry ambiguity, and explicit opt-in.
- Native probe owns a separate test thread; never mutate existing user threads.
- No release, version bump, installed-plugin modification, commit, push or public PR before the applicable approval.

## Review focus

- A configured version differs from the daemon response: refuse.
- An unmeasured patch or a misleading user-agent prefix: refuse.
- Secondary receives a primary tool/approval callback: fail the probe.
- Native callback observation is missing: inconclusive, not supported.
- Child event or changed socket generation: preserve existing rejection.

After restart, a real 15-second CodeScout background job ended with exit 0 and marker CODEX_WAKE_LIVE_TEST_OK; its automatic notification resumed the idle session without a new user message. The receipt records continuation_observed and one send attempt. Receipt completed and active-turn completion are not claimed.

Ruling: thread/start alone creates no resumable rollout on the observed daemon, so the native probe starts its one bounded turn before secondary attachment. Callbacks arriving before secondary close are inconclusive. Thread-local hooks are disabled so installed routing hooks do not intercept the harmless approval request; this does not change profile configuration.
